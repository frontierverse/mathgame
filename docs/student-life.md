# 학생 생활 · 마음 쉼터

`/life`는 실제 학생 생활 공간이고, `/life/demo`는 가상 학생 4명으로 기능을 확인하는 체험 화면입니다. 체험 화면도 같은 관리자 비밀번호를 서버에서 확인하지만 실제 관리자 세션을 만들거나 학생 저장소를 읽지 않으며, 새로고침하면 초기화됩니다.

## 운영 준비

1. 기존 Supabase 프로젝트에 `supabase/migrations/202609170001_create_student_mood.sql`과 `supabase/migrations/202609170002_create_student_life_hidden_youth.sql`을 순서대로 적용합니다. 마이그레이션은 기분 기록용 `StudentMood`, 마음 쉼터 숨김 목록용 `StudentLifeHiddenYouth`, 로그인 세션용 `StudentLifeSession`, 로그인 시도 제한용 `StudentLifeLoginThrottle`을 추가합니다. `Youth.id`의 `text` 타입을 사용하며, 기존 학생·학습 기록은 수정하지 않습니다.
2. 서버 환경 변수에 `LIFE_ADMIN_PASSWORD`, `AUTH_SECRET`(32자 이상), `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`를 설정합니다. 현재 로컬 관리자 비밀번호는 별도의 `.env.local`에 설정되어 있습니다. 비밀번호·서명 키·서비스 키는 `NEXT_PUBLIC_`로 노출하지 않습니다.
3. 앱을 재시작합니다. 배포 시 HTTPS를 사용합니다. 설정이 빠지면 실제 명단·기록과 체험 로그인이 모두 닫힙니다.

관리자는 비밀번호를 직접 입력해 입장하고 학생을 선택한 뒤 **학생 입력 시작**을 누릅니다. 서버는 기존 관리자 세션 행이 실제로 삭제된 것을 확인한 뒤에만 선택된 학생 한 명의 입력 전용 세션을 만듭니다. 학생이 **마치기**를 누르면 입력 세션 행도 지웁니다. 따라서 이미 로그아웃된 관리자 쿠키를 다시 사용해도 관리자 기록을 열 수 없으며, 다음 학생 선택 및 기록 조회에는 관리자 비밀번호를 다시 입력해야 합니다. 로그인 양식은 비밀번호 자동 완성을 요청하지 않습니다.

학생 이름·점수·비밀번호는 localStorage에 저장하지 않습니다. 브라우저의 HTTP-only, SameSite=Strict 세션 쿠키에는 32바이트 임의 토큰만 들어갑니다. 데이터베이스에는 원문 토큰 대신 SHA-256 해시와 역할, 학생 ID, 만료 시각만 저장하며 서버가 요청마다 이 행을 확인합니다. 학생 입력 세션은 20분, 관리자 세션은 최대 1시간이고 자동 갱신하지 않습니다. 모든 데이터 응답은 `private, no-store`입니다. 로그인은 실제 화면과 체험 화면이 같은 서버 측 시도 제한을 사용합니다. 한 접속 위치에서 10분 안에 5회 실패하면 5분 동안 잠기고, 접속 주소를 바꾸더라도 전체 20회 실패 시 같은 잠금이 적용됩니다. 원래 접속 주소 대신 서버에서 만든 HMAC 해시만 저장합니다. 만료된 세션과 오래된 시도 제한 행은 인덱스를 이용해 운영 환경에서 주기적으로 삭제할 수 있습니다. 담당 시설별 권한·관리자 개인별 계정·상담자별 감사 로그는 포함하지 않습니다. 기존 학습 기능의 접근 방식은 변경하지 않습니다.

## 기록 공개

- 학생 목록에는 이름과 기록 여부만 표시합니다. 점수·점수에 따른 표정·개별 확인 제안은 목록에 표시하지 않습니다.
- 관리자 로그인 후에도 개인 기록은 기본으로 가립니다. **기록 보기**를 누르면 관리자 인증을 다시 확인한 후 선택된 학생의 점수·그래프·상담 정보를 표시합니다. 다른 학생 선택, 학생 입력 시작, 창·탭 전환 시 다시 가립니다. 가려진 내용은 화면이나 접근성 트리에 렌더링하지 않습니다.
- 학생 입력 화면에서는 저장된 점수·상담 정보를 API 응답에서도 제외합니다. 저장 완료 화면에는 점수·기분 표정을 표시하지 않습니다. **기록 보기 · 관리자 로그인**으로 선생님과 함께 확인할 수 있습니다.
- 로그인 만료 시 화면을 닫고, 같은 브라우저의 다른 마음 쉼터 탭에도 세션 변경을 알려 남아 있는 관리자 화면을 지웁니다.
- 체험 화면은 비밀번호 확인만 공유하고 가상 데이터와 체험 관리자 전환만 사용합니다. 실제 관리자 세션을 발급하거나 학생 기록에 접근하지 않습니다. 체험 화면에서 학생 입력을 시작할 때도 같은 기기에 남은 실제 관리자 세션은 폐기합니다.

## 기록과 확인 제안

- 0~5 정수 점수와 선택적 대화 요청을 기록합니다. 한국 날짜 기준 학생별 하루 1행이며 당일 재입력은 수정입니다. 요청과 DB 함수 양쪽에서 점수 범위와 날짜를 검증합니다.
- 이름 대신 학생 고유 ID를 사용합니다. 동명이인 기록이 합쳐지지 않습니다.
- `StudentLifeHiddenYouth`에 등록된 학생은 기존 학습 데이터에는 남아 있지만 마음 쉼터 명단·입력·기록 응답·상담 변경에서 제외됩니다.
- 7일·30일·90일·1년 그래프를 제공합니다. 미기록 날짜는 0점으로 대체하지 않고 선을 끊습니다. 날짜별 점수 목록도 펼칠 수 있습니다.
- 오늘 또는 어제의 최신 기록이 0~1점이거나, 그날까지 연속 3일간 2점 이하이거나, 7일 이내 이전 기록 대비 2점 이상 하락하면 확인을 제안합니다. 미완료 대화 요청은 날짜와 무관하게 남습니다.
- 제안 기준은 운영상 안부 확인을 돕는 규칙이며 임상 척도나 진단이 아닙니다. 학생끼리 점수·평균·순위를 비교하지 않습니다.
- 상담 상태는 **확인 전 → 상담 예정 → 확인 완료**입니다. 완료된 기록은 제안에서 빠지고, 학생이 그날 점수나 대화 요청을 바꾸면 다시 확인 전으로 돌아옵니다. 동일 내용 재전송은 기존 상담 상태를 유지합니다.
- 학생을 삭제하면 연결된 기록이 자동 삭제되지 않도록 외래키에 `ON DELETE RESTRICT`를 적용합니다. 시설 퇴소 처리와 기록 보관·삭제 기간은 시설 운영 정책에 맞게 별도 관리해야 합니다.

npx eslint src/app/life src/app/api/life src/app/data/lifeSession.ts src/app/data/studentLife.ts src/app/components/AppHeader.tsx tests/student-life.test.mjs

테스트는 실제 학생 자료를 사용하지 않고 날짜 경계·점수 검증·확인 제안·세션 변조·학생별 API 접근 범위를 확인합니다. 데이터베이스의 실제 영구 저장은 마이그레이션 적용 후 별도로 확인해야 합니다.
